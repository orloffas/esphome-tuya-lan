# esphome-tuya-lan

## Purpose

Внешний компонент ESPHome `tuya_lan`: управление Wi-Fi-розетками Tuya по локальной сети (протоколы 3.3, 3.4, 3.5) без облака Tuya и без Home Assistant в цепочке. Хаб держит соединение с каждой розеткой, поверх него работают платформы `switch`, `sensor` и `binary_sensor`. Лицензия MIT, репозиторий публичный: `orloffas/esphome-tuya-lan`.

## Key Files

| Path | Description |
|------|-------------|
| `components/tuya_lan/tuya_protocol.*` | Чистое ядро протокола: кадры, шифрование, HMAC/GCM. Без зависимостей от ESPHome — собирается отдельно для host-теста |
| `components/tuya_lan/tuya_lan.*` | Хаб ESPHome: соединение с розеткой, FreeRTOS-задача |

| `README.md` | Публичный README: английская половина, затем русская в том же файле |

## For AI Agents

### Working In This Directory

- **Репозиторий публичный.** Не коммитить `local_key`, `device_id`, адреса розеток, абсолютные пути с именем пользователя, имена машин, фрагменты логов с реальными данными. В тестах и примерах — выдуманные значения и `!secret`.
- Ядро протокола не должно зависеть от ESPHome: иначе host-тест не соберёт его отдельно.
- Любое изменение оформляется через `git commit`; выполненную работу не оставлять незакоммиченной.
- Внешние документы (`CONTRIBUTING`, `SECURITY`, `CODE_OF_CONDUCT`, `CHANGELOG`) ведутся парами `*.md` + `*.ru.md`; правка одного без второго — незакрытая задача.

### Testing Requirements

- **Перед коммитом любого изменения протокола обязателен** `make -C tests/host test`. Нужны mbedtls (`brew install mbedtls@3`) и `uv`; фикстуры Makefile генерирует сам.
- Изменения в хабе, платформах и схеме проверяются `esphome compile .github/test/compile-test.yaml`.
- Зелёные тесты не заменяют проверку на живой розетке; её делаем только с разрешения владельца.

### Common Patterns

- Протокол и транспорт разделены: `tuya_protocol.*` строит и разбирает кадры, `tuya_lan.*` отвечает за сокет, переподключение и состояние.
- Каждая платформа — каталог с `__init__.py` (схема ESPHome) и привязкой к хабу через `tuya_lan_id`.
- Эталон поведения протокола — `tinytuya`: расхождение с ним по байтам считаем багом кодека.

## Language Policy

Общение с владельцем, внутренняя документация, `AGENTS.md`, `STATE.md` и обсуждение коммитов — на русском. Код, комментарии в коде, `README.md` (английская половина), `CONTRIBUTING.md` и сообщения коммитов — на английском. Идентификаторы, имена API и команды не переводятся.

## Git Workflow

Trunk-based: `main`, работа через pull request, merge только squash, CI (`host-tests`, `esphome-compile`) зелёный до merge. Сообщения коммитов и PR — на английском. Ветка нужна для рискованного или незавершённого; задача закрыта, когда работа влита, а ветка удалена.

## Public Repository

- Никаких секретов розеток (`local_key`, `device_id`, адреса), абсолютных путей с именем пользователя, имён машин.
- Агентские артефакты (`.omc/`, транскрипты, планы) не коммитятся — они в `.gitignore`.
- Обе половины `README.md` совпадают по смыслу: правка английской без русской — незакрытая задача.
- Вкладки на главной странице репозитория GitHub формирует сам по фиксированному списку имён файлов, поэтому переключение языка живёт ссылкой в первой строке каждого документа.
