## [0.1.2] - 2026-10-18

### Добавлено

- Действие `tuya_lan.release` и методы `release_dp(dp)` / `release_all()` — сбрасывают сохранённое намерение записи у хаба, чтобы он перестал досылать DP после возврата управления другому контроллеру (например, Home Assistant); выключатель продолжает следовать отчётам самой розетки.
- `has_pending_writes()` — истинно, пока желаемое значение DP не подтверждено розеткой.

## [0.1.1] - 2026-10-18

### Исправлено

- Протокол 3.3: кадр с пустым payload (ack heartbeat или CONTROL — это только retcode) принимается, а не отбрасывается с предупреждением каждые 10 с; непустой кадр, который не расшифровался, по-прежнему отвергается.
- Пустой 3.3-кадр больше не считается подтверждением, что устройство на связи: его CRC неключевой и может быть подделан в локальной сети, что исказило бы датчик `online`; признак жизни теперь держится на аутентифицированных или непустых кадрах.
- Таймаут живости стал адаптивным к `poll_interval` (`max(30с, 2 × poll_interval + 5с)`), чтобы большой интервал опроса не вызывал ложных разрывов.
- Пример и README: датчику мощности дано имя, отличное от выключателя; в русский сниппет README добавлены явные `id`, чтобы имена целиком из кириллицы не схлопывались в пустой ASCII object id.

## [0.1.0] - 2026-10-17

### Добавлено

- **Компонент ESPHome `tuya_lan`:** хаб, который держит локальное соединение с каждой Wi-Fi-розеткой Tuya, и платформы `switch`, `sensor` и `binary_sensor` поверх него. Без облака Tuya и без Home Assistant в цепочке.
- **Локальные протоколы Tuya 3.3, 3.4 и 3.5.**
- **Host-тесты кодека протокола,** сверенные байт в байт с [tinytuya](https://github.com/jasonacox/tinytuya), включая негативные случаи (завёрнутая длина, подделка тега/HMAC/CRC, обрезанные кадры). Запуск: `make -C tests/host test`.
- **Сетевой обмен с оглядкой на безопасность:** весь обмен в задаче FreeRTOS, `loop()` не блокируется; состояние выключателя публикуется только по подтверждению розетки; команда хранится как желаемое состояние и переигрывается после реконнекта, так что OFF не теряется; аппаратный ГСЧ для GCM-nonce в 3.5; разбор недоверенных кадров с проверкой границ.
- **Пример для двух розеток** в `example/`; учётные данные берутся из `!secret`.
- **CI:** host-тесты и `esphome compile` тестовой конфигурации.
